# KnowledgeHub – AI Document Assistant

**KnowledgeHub** is a full-stack AI-powered document management and question-answering platform built with Next.js, NestJS, Prisma, and PostgreSQL.

It allows authenticated users to upload PDF and DOCX documents, extract their contents, divide text into smaller chunks, generate and store vector embeddings, search document content, and ask questions using a Retrieval-Augmented Generation (RAG) pipeline.

The project is being developed as a practical learning project to explore modern full-stack engineering, backend architecture, document processing, vector search, and LLM-powered applications.

> **Current development status:** Document management, upload and extraction, chunking, embedding storage, search, and the QA workflow have been implemented. Mock providers are currently used for local development. Real semantic retrieval and AI-generated answers require an active AI provider with available API credits.

## How KnowledgeHub Works

### 1. User Authentication

Users register and log in through the backend API.

Authentication includes:

- JWT access tokens.
- Refresh tokens.
- HTTP-only cookies.
- Password hashing using bcryptjs.
- Passport JWT strategy.
- Protected API endpoints.

The frontend uses a shared authentication context and protected route components to manage authenticated access.

### 2. Document Upload

Authenticated users can upload PDF and DOCX documents.

The upload workflow:

1. User selects a document.
2. Frontend validates the file type and size.
3. The document is sent using multipart/form-data.
4. Multer receives and stores the uploaded file.
5. The backend creates a document record.
6. The document enters the processing workflow.

Supported formats:

- PDF
- DOCX

Maximum upload size: **10 MB**.

### 3. Text Extraction

The `DocumentTextExtractorService` extracts text from uploaded documents.

Libraries:

- `pdf-parse` for PDF extraction.
- `mammoth` for DOCX extraction.

Extracted text is stored in the `Document` record.

Document processing statuses:

```text
UPLOADED
    |
    v
PROCESSING
    |
    v
READY

Processing failure
    |
    v
FAILED
```

### 4. Document Chunking

Large documents are divided into smaller text segments using the `DocumentChunkingService`.

Current configuration:

| Setting | Value |
|---|---:|
| Chunk size | 1,200 characters |
| Chunk overlap | 200 characters |

The chunking service attempts to split content at paragraph, sentence, or word boundaries.

Chunk overlap preserves context between neighboring segments.

Each chunk is stored separately in PostgreSQL and associated with its original document.

### 5. Embedding Generation

Embeddings represent text as numerical vectors that can be compared mathematically.

The `EmbeddingsService` supports two providers.

**OpenAI provider**

- Model: `text-embedding-3-small`
- Dimensions: 1,536

**Mock provider**

- Uses deterministic SHA-256-based vector generation.
- Does not understand text meaning.
- Useful for local development and automated testing.
- Does not require OpenAI API credits.

The provider is configured through the `EMBEDDINGS_PROVIDER` environment variable.

### 6. Embedding Storage

Generated vectors are stored in PostgreSQL using JSONB.

The `DocumentChunk` model includes:

| Field | Purpose |
|---|---|
| `content` | Original chunk text |
| `chunkIndex` | Position of the chunk |
| `charCount` | Character count |
| `embedding` | Numerical vector |
| `embeddingModel` | Provider/model identifier |
| `embeddedAt` | Embedding generation timestamp |

This allows the application to reuse stored embeddings instead of generating them repeatedly.

### 7. Search and Retrieval

The Search module accepts natural-language queries.

The workflow:

1. Receive the user's query.
2. Generate an embedding for the query.
3. Retrieve eligible document chunks belonging to the authenticated user.
4. Compare the query vector against stored chunk vectors.
5. Calculate cosine similarity.
6. Sort results by similarity.
7. Return the highest-ranked chunks with source document information.

Cosine similarity:

```text
similarity(A, B) = (A · B) / (||A|| × ||B||)
```

**Current limitation:** The search implementation works with the mock provider, but meaningful semantic relevance requires real embeddings. Mock similarity scores should not be interpreted as actual semantic relevance.

### 8. Retrieval-Augmented Generation (RAG)

KnowledgeHub includes a QA module that combines document retrieval with an answer-generation workflow.

The intended RAG process:

```text
User asks a question
        |
        v
Generate query embedding
        |
        v
Retrieve relevant document chunks
        |
        v
Build context with source references
        |
        v
Send question and context to LLM
        |
        v
Generate a context-aware answer
        |
        v
Return answer with citations
        |
        v
Display response in Chat UI
```

The QA service:

- Validates questions.
- Retrieves relevant document chunks.
- Builds context from retrieved content.
- Generates source citations.
- Supports a mock response provider.
- Includes OpenAI Chat Completions integration.
- Handles API errors.

**Current implementation status:** The complete QA request and retrieval pipeline has been implemented and tested using the mock provider. OpenAI answer generation is integrated in code but is not currently active in the project configuration.

### 9. Chat Interface

The Next.js chat interface connects to the QA API.

It provides:

- Question submission.
- Example questions.
- Loading indicators.
- Error messages.
- Answer rendering.
- Citation display.
- Navigation to source documents.

### 10. Document Management

Users can manage their uploaded documents through the dashboard and document pages.

Available operations:

- List uploaded documents.
- View document details.
- Read extracted text.
- Inspect individual chunks.
- Generate embeddings.
- View embedding progress.
- Delete documents with confirmation.

Document deletion also removes associated document chunks through the configured database relationship.

## Database Design

The core Prisma models are:

### User

Stores registered user information and document ownership relationships.

### RefreshToken

Stores hashed refresh tokens and their expiration/revocation information.

### Document

Stores:

- Document metadata.
- Original filename.
- MIME type.
- File size.
- Processing status.
- Extracted text.
- Upload timestamps.
- User relationship.

### DocumentChunk

Stores:

- Extracted text segments.
- Chunk indexes.
- Character counts.
- Embedding vectors.
- Embedding model metadata.
- Embedding timestamps.
- Parent document relationship.

Main relationships:

```text
User
 |
 | 1:N
 |
Document
 |
 | 1:N
 |
DocumentChunk
```

## Getting Started

### Prerequisites

Install:

- Node.js 24+
- npm
- PostgreSQL
- Git
- VS Code or another code editor

### 1. Clone the Repository

```bash
git clone https://github.com/raselcsedev/knowledgehub.git

cd knowledgehub
```

### 2. Install Dependencies

Install backend dependencies:

```bash
cd apps/api
npm install
```

Install frontend dependencies:

```bash
cd ../web
npm install
```

### 3. Configure Environment Variables

Create a root `.env` file:

```env
DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/knowledgehub?schema=public"
JWT_SECRET="your-secure-secret"
```

Create `apps/api/.env`:

```env
OPENAI_API_KEY="your-openai-api-key"

EMBEDDINGS_PROVIDER="mock"
QA_PROVIDER="mock"
QA_MODEL="gpt-4o-mini"
```

Do not commit real API keys, passwords, JWT secrets, or environment files.

The mock providers can be used for development without making paid OpenAI API calls.

### 4. Configure the Database

From the project root:

```bash
npx prisma migrate dev
npx prisma generate
```

Open Prisma Studio:

```bash
npx prisma studio
```

### 5. Start the Backend

```bash
cd apps/api

npm run start:dev
```

Backend:

`http://localhost:3001/api`

Swagger:

`http://localhost:3001/api/docs`

### 6. Start the Frontend

Open another terminal:

```bash
cd apps/web

npm run dev
```

Frontend:

`http://localhost:3000`

## Important Development Notes

- PostgreSQL is used for document and embedding persistence.
- Prisma 7 manages database access and migrations.
- Embeddings are stored in JSONB.
- pgvector integration is deferred to a future development stage.
- Mock embeddings are not suitable for evaluating semantic-search quality.
- Real OpenAI embeddings require a valid API key and available API credits.
- The QA module currently uses the mock provider.
- Real LLM-generated answers require configuring the OpenAI QA provider and a working API account.
- Uploaded documents should be treated as private user data.
- Protected document operations must enforce authenticated user ownership.
- Public demo accounts should use restricted permissions and non-sensitive sample documents.
